Felix — Phase 1 Plan

Repo-agnostic behavioral PR-verification engine. It builds, runs, and verifies a PR against a human-authored spec — running parallel to CodeRabbit, which only reads the diff.

Felix is complementary to CodeRabbit. CodeRabbit reasons over the text of the diff. Felix actually executes the PR head in a sandbox and asks: does the running code satisfy what a human asked for?

1 What "verify" means

Felix produces one of four verdicts per PR (these are the exact values stored in felix_verdicts.verdict):

VERIFIED

All hard Tier 1 checks pass and the cross-family judge confirms every mapped acceptance criterion is met by the running code.

NOT VERIFIED

A hard check failed (build/tests red) or the judge finds one or more criteria unmet. Comes with a "Required to pass" list.

INSUFFICIENT EVIDENCE

No spec could be found, or install/build broke so behavior could not be exercised. Felix declines to bless or block.

SKIPPED

Only non-behavioral files changed (docs, lockfiles, images per skipGlobs). Nothing to run.

2 Pipeline

1
Resolve PR
Fetch metadata, changed files, head/base SHA, and the unified diff via the GitHub client.
2
Load config
Read felix.config.json from the target repo root (install/test/smoke commands, skipGlobs, timeouts). Fall back to the example for Node repos.
3
Triage
If every changed path matches skipGlobs → SKIPPED early, no sandbox spun up.
4
Load spec (Tier 2 mapping)
Extract acceptance criteria from the PR body and linked issues. Map each criterion to changed files / tests → criteria_total, criteria_mapped.
5
Sandbox
git worktree add the head SHA into .felix-worktrees/<pr> — isolated, disposable, no secrets injected.
6
Tier 1 checks
install → build/smoke → full test run → targeted re-run of changed test files → secrets scan. Each emits {name,tier,status,hard,detail}.
7
Tier 3 judge
Cross-family LLM (OpenAI) reads spec + diff + test/smoke output and rules each criterion met/unmet. Refuses to run with an Anthropic judge.
8
Compose verdict
Deterministic rules combine Tier 1 + Tier 3 into the final verdict and a "Required to pass" bullet list.
9
Log + report
Write a felix_verdicts row (best-effort). Dry-run prints the comment; otherwise post/update an idempotent PR comment.

3 Module map

Layout under felix/. CommonJS throughout, matching the repo. Each module is small, single-purpose, and unit-testable in isolation.

│  ├─ index.js               # orchestrator: the 9-step pipeline

github.js — PR + issue read, comment upsert
  • Plain fetch against api.github.com with Authorization: Bearer ${GITHUB_TOKEN} and a User-Agent — same shape as sampulse/integrations/github.js.
  • getPR(owner,repo,n), getFiles(), getDiff() (Accept: application/vnd.github.v3.diff), getIssue().
  • upsertComment() — finds an existing comment by a hidden marker (<!-- felix-verdict -->) and PATCHes it, else POSTs. Write only when FELIX_POST_COMMENT=true and not dry-run.
  • Handles 403 rate-limit + 404 gracefully (return null), mirroring existing helper.
spec.js — spec discovery & Tier 2 mapping
  • Sources, in priority order: PR body "Acceptance Criteria" / checklist section → linked issues (#123, Closes #) bodies → PR title as a weak fallback.
  • Parse markdown checkboxes / bullet lines into discrete criteria strings → criteria_total.
  • Map each criterion to changed files/tests by keyword + path heuristics → criteria_mapped. Unmapped criteria flag possible missing coverage.
  • Records spec_source (e.g. "GitHub issue #123") or null → drives INSUFFICIENT EVIDENCE.
sandbox.js — isolated worktree
  • git fetch the PR head, then git worktree add .felix-worktrees/<repo>-<pr> <headSha>.
  • Disposable + git-ignored. teardown() runs git worktree remove --force in a finally.
  • No .env / secrets copied in. Commands run with a clean, minimal environment.
tier1.js — deterministic checks
  • Each step uses util/exec with the per-command timeout from config and captures combined output (truncated for the judge + comment).
  • install (hard), build/smoke (hard if a smoke expect string is configured), test full run (hard), testOne on each changed test file (soft, for fast signal), secrets scan (hard) honoring secrets.allowFiles.
  • Emits the array stored verbatim in tier1_results.
judge.js — cross-family integrity
Hard guard: if FELIX_JUDGE_FAMILY resolves to Anthropic (or the model id looks like Claude), Felix throws and refuses to run. The judge must be a different model family than the code generator to avoid self-grading.
  • Phase 1 implements the openai family only (FELIX_JUDGE_MODEL=gpt-4.1).
  • Prompt = spec criteria + diff + Tier 1 outputs; structured JSON response {assessment, criteria:[{text,met}]} stored in tier3.
  • If OPENAI_API_KEY is missing → judge step is skipped and feeds INSUFFICIENT EVIDENCE rather than crashing.
verdict.js + comment.js + log.js
  • verdict.js: pure function over (triage, tier1, tier3) → see decision table below. Builds required_to_pass from failed hard checks + unmet criteria.
  • comment.js: renders a compact markdown report (verdict badge, criteria table, failing checks, "Required to pass") + the hidden idempotency marker.
  • log.js: inserts one felix_verdicts row via @supabase/supabase-js; on missing env it warns and continues (per .env.example).

4 Verdict decision table

ConditionVerdict
Only skipGlobs paths changedSKIPPED
No spec found or install/build failed (can't exercise behavior)INSUFFICIENT EVIDENCE
Any hard Tier 1 check failedNOT VERIFIED
Judge marks ≥1 mapped criterion unmetNOT VERIFIED
All hard checks pass and all mapped criteria metVERIFIED

Precedence top→bottom: the first matching row wins, so SKIPPED short-circuits before any sandbox cost, and INSUFFICIENT EVIDENCE is preferred over a false NOT VERIFIED when the system couldn't actually test.

5 CLI surface

# dry-run a PR (default): compute + print, never comment
node bin/felix.js Eatmorerats/sampulse#42

# post/update the verdict comment on the PR
node bin/felix.js Eatmorerats/sampulse#42 --post

# point at a target repo checkout for config + sandbox
node bin/felix.js owner/repo#7 --repo-path /path/to/clone

Flags resolve against env: --post ⇒ FELIX_POST_COMMENT=true + FELIX_DRY_RUN=false. Defaults stay safe (dry-run, no write) per .env.example.

6 Build sequence (commits)

  1. util + config + github client — exec, logger, config loader/validator, GitHub read/comment. Unit tests on fixtures.
  2. spec loader + Tier 2 mapping — criteria extraction + mapping, spec_source.
  3. sandbox + Tier 1 — worktree lifecycle, the five checks, output truncation.
  4. judge + verdict + comment — cross-family guard, decision table, markdown render.
  5. orchestrator + CLI + Supabase log — wire the pipeline, arg parsing, best-effort logging.
  6. tests + docs + apply schema — end-to-end on a fixture PR; run felix-schema.sql via config/run-schema.js.

Each commit keeps npm test green and the engine importable, so review can happen incrementally.

7 Risks & decisions

Untrusted PR code execution. Tier 1 runs arbitrary install/test scripts. Phase 1 is hand-run by you on trusted repos only — no auto-trigger, no secrets in the sandbox, generous timeouts but hard kill. Stronger isolation (container/VM, network egress limits) is a later phase.
Cross-family integrity. The Anthropic-judge refusal is a load-bearing safety rule, not a config nicety — it prevents the generator family from grading its own output.
  • Cost. Judge runs one bounded LLM call per PR; diff + outputs are truncated to a token budget.
  • Idempotency. Re-running on the same PR updates the single marked comment rather than spamming.
  • Private repo. Pages/raw-HTML hosting isn't available, so docs like this are committed in-repo and delivered directly for mobile viewing.
  • Graceful degradation. Missing Supabase or judge keys downgrade the verdict honestly (warn / INSUFFICIENT EVIDENCE) instead of crashing.
